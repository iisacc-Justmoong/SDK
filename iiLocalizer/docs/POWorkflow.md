# PO 번역 작업 흐름과 호환 범위

## 참고한 방식과 현재 상태

[KDE KI18n](https://api.kde.org/ki18n-index.html)은 GNU gettext에 기반한 UI
텍스트 국제화 모듈이다. KDE의 [번역 안내](https://develop.kde.org/docs/plasma/widget/translations-i18n/)는
번역 대상 원문, `%1`과 같은 위치 인자, 복수 메시지와 번역 템플릿 추출을 설명한다.
GNU gettext의 [PO 파일 형식](https://www.gnu.org/software/gettext/manual/html_node/PO-Files.html)과
[복수형 규칙](https://www.gnu.org/software/gettext/manual/gettext.html)은
번역 자료의 기준이다. 이 문서는 해당 개념을 iiLocalizer에 적용하는 설계이며
KDE 코드를 가져왔다는 뜻이 아니다.

현재 단수 메시지에 한정한 PO 판독기와 위치 인자 치환기가 구현되어 있다. 추출기,
전용 검사기, 복수형 판독, 배포 도구와 실제 제품 통합은 아직 제공되지 않는다.
구현된 범위와 검증 결과는 [현재 구현](Implementation.md)을 따른다.

## 자료의 역할

- 애플리케이션 원문은 완전한 메시지 단위로 작성한다. 단어 조각을 먼저 결합한 뒤
  번역하거나 번역문을 조각내어 결합하지 않는다. 동적으로 바뀌는 값은 위치 인자로
  넘겨 번역가가 문장 안의 순서를 조정할 수 있게 한다.
- `.pot`은 번역 대상 원문을 모은 템플릿이고, `.po`는 특정 언어에 대한 원문과
  번역의 편집 가능한 카탈로그이다. GNU gettext의 `.mo`는 `.po`에서 생성할 수
  있는 이진 카탈로그이다. `.po`와 `.mo`를 같은 파일 형식으로 취급하지 않는다.
- iiLocalizer는 단수 메시지에 대해 **`.po` 직접 판독**을 제공한다. `.mo` 생성은 기존 gettext
  도구와의 교차 검증 또는 다른 소비자를 위한 선택적 작업이며, `.mo`를 iiLocalizer가
  읽을 수 있다고 가정하지 않는다. 사용자가 편집하는 번역 원본은 `.po`이다.
- 도메인은 애플리케이션 또는 모듈이 소유하는 메시지 묶음이다. 도메인 이름, 파일
  위치, 언어 선호, 리소스의 소유권은 호스트가 정한다. 파일 이름만으로 언어 또는
  도메인을 결정하지 않는다.

## PO 예시

다음은 전체 목표를 설명하기 위한 UTF-8 한국어 복수형 카탈로그이다. 현재 판독기는 복수 항목을 거부한다.

```po
msgid ""
msgstr ""
"Content-Type: text/plain; charset=UTF-8\n"
"Language: ko\n"
"Plural-Forms: nplurals=1; plural=0;\n"

#. 파일을 여는 동작이다.
msgctxt "file-menu/verb"
msgid "Open"
msgstr "열기"

msgid "%1 file"
msgid_plural "%1 files"
msgstr[0] "파일 %1개"
```

문맥 `file-menu/verb`와 원문 `Open`을 조회하면 해당 번역은 `열기`이다. 복수
조회에 수량 `3`과 문자열 인자 `3`을 각각 전달하면 한국어 번역의 선택 결과는
`파일 %1개`, 치환 결과는 `파일 3개`이다. 수량을 전달하는 것만으로 치환 인자가
자동 추가되지는 않는다. 위 결과는 계약의 예측 결과이며 실행 검증 결과가 아니다.

## 최초 구현의 PO 입력 계약

- 입력 바이트와 텍스트는 UTF-8이다. 헤더에 문자 집합이 선언되어 있다면 UTF-8과
  일치해야 한다. 다른 문자 집합은 자동 변환하지 않고 오류로 보고한다. 문자 집합이
  없는 입력은 UTF-8로 읽으며 UTF-8 BOM은 거부한다.
- PO 헤더, `msgctxt`, `msgid`, 단수 `msgstr`, 여러 줄 문자열, 지원하는 이스케이프와
  일반 주석을 처리한다. `msgid_plural`과 `msgstr[N]`은 명시적으로 거부한다.
  이스케이프 목록은 [현재 구현](Implementation.md)을 따른다. 헤더는 빈 `msgid`의
  `msgstr`이다. 오류 위치는 알려진 경우 1부터 시작하는 행 번호로 제공한다.
- `#, fuzzy` 또는 `#= fuzzy`로 표시한 항목, 비어 있는 번역 및 `#~` obsolete 항목은 사용자에게 표시할
  번역으로 사용하지 않는다. 번역 중인 항목을 무조건 문법 오류로 취급하지 않는다.
  복수 항목의 부분 번역은 현재 지원하지 않는다.
- 후속 복수형 구현에서는 유효한 `Plural-Forms` 헤더의 수식으로 번역 인덱스를
  선택한다. 표현식과 인덱스의 목표 계약은 [현지화 계약](LocalizationContract.md)을 따른다.
- 같은 문맥·원문의 중복, 유효하지 않은 UTF-8, 파싱 불가능한 항목 또는 다른 문자
  집합은 파서가 거부한다. PO `Language`와 대상 언어의 일치 여부는 호스트가 확인한다.
  LVUI 예제는 불일치할 때 기존 문자열 저장소를 변경하지 않는다. 현재 자원 한도는
  [현재 구현](Implementation.md)을 따르며 한도 설정 인터페이스는 아직 없다.
- 이 범위는 일반적인 gettext PO 작업을 목표로 하며 GNU gettext의 모든 확장,
  비 UTF-8 인코딩, KDE KUIT 마크업과 번역 스크립트까지 지원한다는 뜻이 아니다.
  지원하지 않는 확장을 무시해 의미가 바뀌는 경우는 명시적으로 거부해야 한다.

## 번역에서 배포까지의 목표 흐름

아래의 추출과 자동 검사는 아직 iiLocalizer가 제공하는 도구가 아니다.

1. 개발자는 사용자에게 표시되는 완전한 원문과 필요한 문맥, 복수 원문, 위치 인자를
   코드에 표시한다. 문맥과 원문은 번역 항목의 식별자이므로 변경하면 기존 번역의
   재검토가 필요하다.
2. 추출 도구는 표시된 원문과 번역가를 위한 설명을 도메인별 `.pot`으로 생성한다.
   C++ 및 Python 원문과 향후 LVUI 원문을 추출하는 구체적인 표기와 도구는 아직
   정하지 않았다. 지원 언어별 자동 추출이 구현될 때까지 수작업 PO도 가능하다.
3. 번역가는 각 대상 언어의 `.po`를 갱신하고 문맥, 복수 형태와 위치 인자를 확인한다.
   `fuzzy`는 검토가 필요하므로 번역가가 확인하기 전에는 배포 번역에 쓰지 않는다.
4. 자동 검사는 PO 구문, 헤더와 복수식, 동일 키 중복, 지원하는 위치 표시와 인자
   번호를 점검한다. 일반 gettext 검사만으로 iiLocalizer의 모든 치환 규칙이
   검증된다고 가정하지 않는다. gettext 도구는 개발·교차 검증에 쓸 수 있으나,
   플랫폼별 설치 및 라이선스 조건은 별도로 확인한다.
5. 호스트는 검증된 `.po`와 언어 태그·도메인을 리소스 공급 인터페이스로 전달한다.
   언어·카탈로그가 바뀌면 변경 이벤트를 관찰하는 뷰모델이 필요한 메시지를 다시
   조회한다. 언어 목록과 번역 파일의 실제 배포는 소비 애플리케이션의 책임이다.

소스나 번역을 가져올 때는 각 자료의 출처와 라이선스를 별도로 확인한다. KDE의
작업 흐름을 참조했다는 사실만으로 KDE의 코드나 번역문을 자유롭게 재배포할
권한이 생기지는 않는다.
