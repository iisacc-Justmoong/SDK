# LVUI 레이블 치환의 첫 구현 범위

## 목적과 경계

이 단계에서 PO로 번역한 문자열과 실행 인자를 LVUI의 실제 `Label` 바인딩까지
전달하는 첫 번째 경로를 구현하였다. [전체 현지화 계약](LocalizationContract.md)의
모든 기능을 이 단계에 구현했다고 해석하지 않는다. 특히 복수형 수식, `.mo`, 자동
추출, OS 언어 감지, 제품 UI와 자동 카탈로그 감시는 후속 범위이다.

`iiLocalizer`는 UTF-8 PO 바이트를 받아 단수 메시지를 읽고 `%1`부터 시작하는
위치 인자를 치환하는 독립 C++23 라이브러리와 동일 동작의 Python API를 제공한다.
LVUI나 iiGUI를 링크하지 않는다. 파일 IO와 사용하는 언어·도메인 선택은 호스트가
책임진다. C++·Python 모두 읽은 카탈로그가 유효하지 않으면 오류를 받는다.

## 입력과 치환

- 이 단계의 PO 파서는 헤더, 단수 `msgid`·`msgstr`, 선택적인 `msgctxt`, 여러 줄
  문자열, 빈 번역, `#,` 및 `#=`의 `fuzzy` 플래그, `#~` obsolete 항목을 다룬다.
  빈 헤더를 일반 메시지로 조회하지 않는다. 같은 문맥·원문이 중복되거나 UTF-8,
  이스케이프 또는 항목 문법이 잘못되면 카탈로그 전체를 거부한다.
- 문자 집합은 UTF-8이며 PO 헤더의 `Content-Type`에 문자 집합이 있다면 UTF-8만
  허용한다. 헤더의 `Language`는 조회할 수 있도록 보존한다. `msgid_plural`과
  `msgstr[N]`은 이 단계에서 명시적으로 지원하지 않으며 무시하지 않고 거부한다.
  구현에서 인정하는 문자 이스케이프는 API 문서에 명시한다.
- 조회 시 문맥이 없는 원문과 빈 문맥은 구분한다. 번역이 없거나 빈 번역이면
  호출한 원문을 사용한다. `fuzzy`와 obsolete 번역은 사용하지 않는다.
- 선택된 문자열의 `%1`, `%2`, ...는 전달한 값으로 치환하며 순서를 바꿀 수 있다.
  `%%`는 `%`이고 다른 단독 `%`는 그대로 둔다. `%10`은 열 번째 인자이다.
  치환 값은 다시 해석하지 않는다. `%0`, 없는 인자, 숫자 범위 초과는 오류이다.
  번역 문자열의 인자 오류는 원문을 시도하며 원문도 잘못되면 오류를 반환한다.
- 파서와 치환은 유한한 입력 크기를 적용하며 실패 시 반쯤 읽은 카탈로그나
  부분 치환 결과를 성공으로 내보내지 않는다.

## LVUI와의 연결

호스트 테스트는 서로 다른 `localized("toolbar.greeting")`과
`localized("panel.greeting")` 키를 가진 두 `Label`을 LVUI AOT 컴파일러로
네이티브 뷰로 생성한다. 호스트는 두 키를 같은 원문 `Hello, %1`의 서로 다른
사용 위치로 등록한다. PO 바이트를 읽어 만든 iiLocalizer 카탈로그와 인자를
어댑터에 전달하면 선택된 키의 값을 LVUI `AppStrings`에 기록한다. 예제 어댑터는
PO 문맥도 사용 위치와 별도로 전달받는다. LVUI와 iiGUI는
iiLocalizer를 모른다. 헤드리스 검사 하네스는 iiGUI의 내부 위젯 상태 헤더를
사용한다. 어댑터는 애플리케이션 구성 예제로 유지한다.

한국어 PO의 `"Hello, %1" → "안녕하세요, %1님"`에 `"지민"`을 전달하면 네이티브
레이블 상태가 `"안녕하세요, 지민님"`이 되는 것을 확인했다. 같은 언어의 인자가 바뀌어
호스트가 새 결과를 게시하면 활성 레이블도 갱신된다. 다른 언어로 바꿀 때도
호스트가 해당 언어·인자에 맞는 값을 게시한다. 이 예제는 자동 번역 또는 임의의
모델·뷰에 대한 자동 연결을 제공하지 않는다.

## 동일 원문의 사용 위치 선택 계약

같은 원문을 쓰는 레이블이 여러 곳에 있을 때 호스트는 각 사용을 원문, 고유한
사용 위치와 고유한 `AppStrings` 키의 조합으로 등록한다. 사용 위치는 호스트가
소유하는 정확한 식별자이며 예를 들면 `main/toolbar/toolbarGreeting`처럼 뷰와 레이블을
함께 나타낸다. 위치가 같거나 문자열 키를 공유하는 두 등록은 거부한다. 이렇게 해야
한 위치에 쓴 키가 다른 위치를 함께 바꾸지 않는다. 레이블 선언은 해당 사용에
등록한 키를 `localized(...)`에 연결해야 한다. 등록된 키를 등록되지 않은 다른
레이블에서도 쓰면 그 레이블도 갱신되므로, 앱은 실제 소비자 전체에서 키가
해당 사용에만 연결되도록 보장해야 한다.

치환 호출은 원문과 함께 사용 위치를 선택적으로 받는다. 위치를 지정하면 원문과
위치가 모두 일치하는 사용만 바꾼다. 위치를 생략하면 등록된 사용 중 같은 원문을
쓰는 모든 레이블을 바꾼다. 일치하는 사용이 없으면 아무 레이블도 변경하지 않으며
호스트에 일치 항목이 없음을 알린다. 독립 선택 API는 빈 인덱스 목록을 반환하고
예제 어댑터는 `not_found`를 반환한다. 빈 위치는 생략과 다르며 유효하지 않다.
문자열을 이미 번역된 화면 표시값과 비교하지 않고 원문 식별자로 찾는다.

선택과 번역 결과를 검증한 뒤 대상 키를 한 번의 카탈로그 교체로 게시한다. 따라서
잘못된 위치, 중복 등록, 잘못된 인자 또는 잘못된 PO 언어는 일부 레이블만 바꾸지
않는다. 게시 호출은 LVUI `AppStrings`의 UI 소유 스레드에서 수행한다. LVUI의
변경 알림 콜백이 예외를 던진 경우에는 저장소 변경이 이미 확정된
상태에서 실패가 반환될 수 있다. PO의 `msgctxt`는 번역의 의미를 구분하는 별도의 선택 인자이며 사용 위치를
대신하지 않는다. 같은 `Open`이라도 메뉴 위치에 `menu` 문맥을 전달한 결과와 다른
위치의 문맥 없는 결과를 서로 독립적으로 게시할 수 있다. 모듈은 앱의 모든 뷰를 자동 탐색하지 않으므로 전체 변경은 호스트가
등록한 사용 전체를 뜻한다. 재사용된 뷰의 개별 인스턴스까지 구분하려면 호스트가
인스턴스가 포함된 위치와 서로 다른 문자열 키를 제공해야 한다.
기존의 단일 공유 키 생성자는 위치 없는 게시를 계속 지원하지만 개별 사용을
구분할 정보가 없어 위치를 지정한 호출은 거부한다.

선택 기능은 iiLocalizer의 독립 C++ API와 Python API에서 같은 결과를 제공한다.
LVUI 연결은 앱 소유 어댑터가 선택된 키를 `AppStrings`에 게시하며 SDK 간 직접
의존성을 추가하지 않는다.

## 검증

실패하는 단위 테스트를 먼저 작성한 뒤 PO 단수 조회·문맥·누락·fuzzy·복수형
거부·치환 오류와 Python API를 검사했다. 별도 소비자 테스트는 `.lvui`를 실제로
컴파일하고 iiGUI의 네이티브 위젯 트리를 창 없이 구성하여 레이블의 초기값,
한국어 전환, 특정 위치 한 곳의 갱신, 위치 생략 시 같은 원문 전체의 갱신, 누락·중복
위치의 실패와 다른 레이블의 보존을 검사하여 통과했다. 리소스 입력은 `resources/`에 두고 생성된
산출물은 `build/` 아래에 둔다. 헤드리스 위젯 검사는 실제 운영체제 창 표시 또는
어느 제품에 대한 통합 검증이 아니다.
