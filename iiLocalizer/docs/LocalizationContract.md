# iiLocalizer 현지화 계약

## 상태와 목적

이 문서는 전체 현지화 기능의 **목표 명세**이다. 단수 PO 조회와 인자 치환,
C++·Python API 및 LVUI 레이블 소비 경로는 구현되었다. 복수형, 모듈 자체의 언어
목록·변경 구독과 나머지 목표는 아직 구현되지 않았다. 현재 제공하는 동작과
검증 결과는 [현재 구현](Implementation.md)을 우선한다. 아래의 목표 계약은 미구현
항목의 동작을 이미 제공한다는 뜻이 아니다.

iiLocalizer의 목적은 애플리케이션이 제공한 언어 선호와 번역 카탈로그를 이용해
사용자에게 보이는 원문 메시지를 현지화된 문장으로 조회하고 실행 시 인자를
치환하는 것이다. GNU gettext의 `.po` 자료와 KDE KI18n의 원문 기반 번역,
문맥, 복수형 및 위치 인자 개념을 참고한다. 지원 범위와 실제 KDE와의 차이는
[PO 작업 흐름](POWorkflow.md)에 기록한다.

## 책임과 의존성

- C++23 API는 메시지 조회, 카탈로그 교체, 언어 선호 변경 및 변경 관찰을 제공한다.
  Python API는 동일한 네이티브 계약과 결과를 노출한다. 외부에서 자원을 제공하거나
  조회 구현을 교체할 수 있는 인터페이스를 제공한다.
- 다른 SDK, Qt, KDE 및 특정 플랫폼 UI를 직접 참조하거나 공개 타입으로 요구하지
  않는다. 호스트가 파일·패키지·네트워크 등에서 카탈로그를 읽어 모듈에 제공한다.
  제품 저장소나 iiFileProvider와의 결합도 호스트 어댑터가 담당한다.
- 이 모듈은 UI를 그리거나 LVUI를 수정하지 않는다. 호스트 뷰모델은 언어 또는
  카탈로그 변경 이벤트를 관찰하고 영향을 받는 문자열을 다시 조회할 수 있다.
- 날짜, 시간, 통화, 숫자, 단위의 언어별 서식, 양방향 텍스트 레이아웃, 글꼴,
  기계번역 및 번역 편집기는 범위 밖이다. 필요한 서식은 호출자가 준비한 인자로
  전달한다. 메시지 번역과 언어별 데이터 서식은 별개의 책임이다.
- 네이티브 코드에는 C++ 표준 라이브러리와 허용된 의존성만 사용한다. KI18n,
  Qt 또는 GNU libintl의 링크를 전제로 하지 않는다. 새 외부 의존성을 선택하기
  전에는 해당 라이선스와 배포 조건을 별도로 확인한다.

## 카탈로그와 메시지 식별

- 최초 구현의 입력은 UTF-8 GNU gettext `.po` 카탈로그이다. 한 카탈로그는 하나의
  도메인과 하나의 대상 언어에 속한다. 도메인과 언어의 연결은 호스트가 명시한다.
  카탈로그 헤더의 `Language`가 있다면 호스트가 지정한 대상 언어와 모순되는
  자료를 거부하고 진단한다. 한 스냅샷에서 같은 도메인·정규화 언어의 카탈로그가
  중복되면 거부한다. 파일 경로에서 도메인이나 언어를 추측하지 않는다.
- 메시지 식별은 **도메인, 문맥의 존재 여부와 값, 원문 `msgid`**의 조합이다.
  원문 및 문맥은 UTF-8로 정확히 비교하며 대소문자, 공백, 문장부호 또는 유니코드
  정규형을 자동 변경하지 않는다. 문맥이 없는 경우와 빈 문맥은 서로 다르다.
- 같은 원문도 문맥이 다르면 다른 번역이 될 수 있다. 동일 카탈로그에서 같은
  문맥·원문의 중복 정의는 거부한다. 다른 도메인이나 문맥의 항목으로 임의 대체하지
  않는다. `msgid ""`는 PO 헤더용으로 예약하며 일반 메시지로 조회하지 않는다.
- `.po`의 여러 줄 문자열, 주석, 이스케이프, 문맥 및 복수형을 읽고, `#,` 또는
  `#=` 플래그로 표시된 `fuzzy`, 미번역과 obsolete 항목은 사용하지 않는다.
  구체적인 형식과 범위는 PO 문서에 따른다. `.mo` 파일 판독은 최초 구현 요건이
  아니며 별도 기능으로 검토한다.

## 언어 선택과 대체

- 호스트는 우선순위가 있는 언어 태그 목록을 제공한다. BCP 47의 `-`와 관용적인
  POSIX 표기 중 구분자인 `_`는 입력에서 같은 것으로 정규화하고 언어·문자·지역
  서브태그의 대소문자를 정규화한다. 시스템 환경 변수나 전역 로캘을 암묵적으로
  변경하지 않는다. POSIX의 인코딩·수식어가 포함된 태그는 호스트가 명시적으로
  변환한다. 유효하지 않은 태그는 오류로 반환한다.
- 각 선호 언어에서 정확한 태그를 먼저 찾고 뒤쪽 서브태그를 하나씩 제거하며
  상위 태그를 찾는다. 예를 들어 `zh-Hant-TW`는 `zh-Hant-TW`, `zh-Hant`,
  `zh` 순이다. 확장·private-use를 줄일 때는 [RFC 4647 조회](https://www.rfc-editor.org/rfc/rfc4647#section-3.4)의
  한 글자 구분자 처리 규칙을 따른다. 이후 다음 선호 언어를 같은 방식으로 찾으며
  중복 후보는 처음 등장한 순서만 남긴다. 관련 없는 지역이나 문자 체계는 추론하지
  않는다. 입력 태그의 전체 허용 구문과 구식 태그 별칭 처리는 구현 전 테스트에서
  확정하며 지원할 수 없는 태그를 조용히 잘라서는 안 된다.
- 탐색은 도메인과 문맥을 유지한 채 **메시지별**로 수행한다. 후보 언어에 카탈로그가
  있어도 해당 번역이 없거나 사용 불가능하면 다음 후보 언어를 찾는다. 모든 후보에
  없으면 원문으로 대체한다. 지역별 전체 카탈로그를 발견했다는 이유로 상위 언어의
  누락 번역을 차단하지 않는다.
- 단수 조회의 최종 대체는 `msgid`이다. 복수 조회의 최종 대체는 gettext의 원문
  관례에 따라 수가 1이면 단수 원문, 그 외에는 복수 원문이다. 이는 영어식 원문
  복수 규칙이므로 그와 다른 원문 언어는 별도 정책이 정해질 때까지 이 계약의
  복수 원문 대체를 사용하지 않는다.

## 복수형

- 복수 조회는 단수 원문, 복수 원문, 0 이상의 정수 수량과 선택적 문맥을 받는다.
  조회 키는 단수 원문이며 복수 원문은 최종 원문 대체에 사용한다. 카탈로그에서
  얻은 번역의 형식은 그 카탈로그의 `Plural-Forms` 헤더에 있는 `nplurals`와
  `plural` 수식으로 선택한다. 요청 언어가 아니라 실제 선택된 후보 카탈로그의
  규칙을 사용한다.
- 수식은 gettext가 정의한 정수 연산, 비교, 논리 연산, 괄호, 조건 연산과 `n`만을
  제한적으로 해석한다. 임의 코드 실행이나 외부 표현식 평가기를 사용하지 않는다.
  수식·수량을 유한한 자원으로 평가하며, 잘못된 구문·0 나눗셈·범위 밖 결과·자원
  한도 초과는 진단한다. 헤더·수식의 문법 오류는 카탈로그 게시 전에 거부한다.
  특정 수량에서만 드러나는 계산 오류나 범위 밖 인덱스는 조회 시 해당 후보를 건너뛰고
  다음 후보를 시도한다. 이 조회 오류만으로 이미 게시된 스냅샷 전체를 폐기하지 않는다.
  복수 항목에 필요한 헤더가 없거나 유효하지 않아도 조용히 영어 규칙을 적용하지 않는다.
- 해당 수량에 필요한 번역 형태가 비어 있거나 없으면 그 후보는 미번역으로 다루고
  다음 후보를 찾는다. 결과적으로 원문을 사용해야 한다면 위의 원문 대체 규칙을
  따른다. 음수, 정수가 아닌 값 및 표현 가능한 범위를 넘는 수량은 오류이다.

## 인자 치환

- 메시지를 선택한 **후** 호출자가 제공한 텍스트 인자를 `%1`, `%2`와 같은 1부터
  시작하는 위치 표시에 치환한다. 번역가는 표시의 순서를 바꿀 수 있으며, 같은
  표시를 반복할 수 있다. 수량도 자동 삽입하지 않으므로 필요한 경우 호출자가
  명시적인 인자로 전달한다.
- `%` 뒤의 연속된 십진수 전체를 하나의 번호로 해석하므로 `%10`은 `%1`과 `0`이
  아니다. `%%`는 문자 `%` 하나를 나타낸다. 번호가 없는 `%`는 그대로 둔다.
  `%0`, 제공되지 않은 번호, 숫자가 표현 범위를 넘는 표시는 서식 오류이다.
  반환된 치환 인자 내용은 다시 해석하지 않는다.
- 번역의 표시에 오류가 있으면 진단하고 다음 후보 번역을 시도한다. 어느 후보도
  없으면 원문에 치환을 시도한다. 원문에도 오류가 있으면 성공 결과로 숨기지 않고
  오류를 반환한다. 사용하지 않은 추가 인자는 허용한다. 진단의 노출 방식과 구체적인
  오류 타입은 구현 시 API로 정한다.
- 이 표기법은 KDE의 위치 인자에서 영감을 받은 iiLocalizer 계약이다. `%%`를
  포함하여 KDE의 모든 서식·마크업과 호환된다고 주장하지 않는다.

## 상태 변경과 실패

- 카탈로그와 언어 목록의 변경은 전체를 검증한 후 새 불변 스냅샷으로 게시한다.
  형식 오류나 읽기 오류가 있으면 이전에 유효했던 스냅샷을 유지하고 오류를 반환한다.
  파일 읽기 자체는 공급자·호스트 책임이다. 빈 미번역 항목과 `fuzzy`는 카탈로그
  전체를 거부하는 오류가 아니다.
- 서로 다른 스레드의 조회와 교체는 데이터 경합 없이 동작한다. 한 조회는 시작할 때
  얻은 일관된 스냅샷을 사용한다. 성공적으로 상태가 바뀐 후에만 수명에 묶인
  구독자에게 변경 이벤트를 알리고, 모듈 내부 잠금 안에서 외부 콜백을 호출하지
  않는다. 이벤트 구독 해제와 호출 중 객체 수명의 안전성을 보장한다.
- 언어 변경의 저장, 운영체제 설정 추적, 이벤트를 UI 스레드로 전달하는 일은
  호스트 책임이다. 이 모듈은 주기적 폴링이나 전역 프로세스 상태 변경을 요구하지
  않는다.

## 공개 형태와 구현 순서

- 단수 메시지의 `#include <iiLocalizer>`, C++·Python API, 빌드 옵션과 CMake
  매크로 및 `install.sh`는 구현되었다. 나머지 공개 시그니처와 교체 가능한 공급
  인터페이스는 해당 기능의 구현 단계에서 정한다. 빌드 출력은 `build/`, 시험
  입력과 실행 자원은 `resources/`를 사용한다.
- 이 명세 뒤에 실패하는 테스트를 작성하고 구현, 리팩터링, 빌드·자동 테스트,
  문서 갱신 순서로 진행한다. 앱 실행이나 실제 제품 통합을 이 명세의 작성만으로
  완료했다고 간주하지 않는다.

## 전체 계약의 검증 기준

다음 목록은 전체 목표의 검증 기준이다. 현재 통과한 단수·레이블 테스트와 남은
검증 범위는 [현재 구현](Implementation.md)을 따른다.

- 원문 조회, UTF-8 문자, 여러 줄과 이스케이프, 문맥 없음과 빈 문맥의 구분,
  동일 원문의 다른 문맥, 다른 도메인 및 중복 항목 거부를 검사한다.
- 정확한 언어, 상위 태그, 확장 구분자, 선호 목록, 메시지별 누락, fuzzy·obsolete·빈 번역,
  모든 후보가 없을 때 원문으로 대체되는 순서를 검사한다.
- 한 형태를 쓰는 한국어, 두 형태를 쓰는 영어 및 세 형태 이상을 쓰는 언어에서
  `0`, `1`, `2`와 경계값을 검사한다. 후보별 복수 규칙과 불완전한 번역,
  잘못된 수식·0 나눗셈·범위 밖 인덱스를 따로 검사한다.
- 치환 순서 변경, 반복, `%10`, `%%`, 숫자가 아닌 `%`, 인자의 재해석 방지,
  누락 인자, 원문의 서식 오류와 후보 번역에서의 복구를 검사한다.
- 잘못된 입력의 원자적 거부, 자원 제한, 동시 조회와 교체, 구독 수명과 콜백
  재진입을 검사한다. 같은 자료의 C++과 Python 결과 및 오류 의미를 비교한다.
- `.po` 호환 자료는 `resources/`에 두고 GNU gettext 도구의 결과와 교차 검사한다.
  패키지 설치 소비와 `#include <iiLocalizer>`도 테스트하되, 실제 앱 실행은
  사용자가 명시적으로 요청한 경우에만 진행한다.
